# Simplicity, Scope, and Code Clarity

This category groups related concepts for navigation. Category membership does not make every item equally normative.

| Entry | Classification | Summary |
|---|---|---|
| [Avoid Accidental Complexity](../compendium/avoid-accidental-complexity.md) | `principle` | Minimize complexity introduced by implementation choices rather than the problem itself. |
| [Explicit Is Better Than Implicit](../compendium/explicit-over-implicit.md) | `heuristic` | Make important dependencies, state changes, defaults, and control flow visible. |
| [KISS](../compendium/kiss.md) | `heuristic` | Prefer the simplest design that correctly satisfies verified requirements. |
| [Make It Work, Make It Right, Make It Fast](../compendium/make-it-work-right-fast.md) | `process-model` | Sequence development through correctness, design quality, and measured optimization. |
| [Meaningful Names](../compendium/meaningful-names.md) | `heuristic` | Use names that communicate domain meaning, role, and units. |
| [No Magic](../compendium/no-magic.md) | `heuristic` | Avoid unexplained values, hidden side effects, and non-obvious conventions. |
| [Principle of Least Astonishment](../compendium/principle-of-least-astonishment.md) | `principle` | Design behavior and interfaces to match reasonable user expectations. |
| [Self-Documenting Code](../compendium/self-documenting-code.md) | `heuristic` | Express intent through structure, names, types, and explicit control flow. |
| [Single Level of Abstraction](../compendium/single-level-of-abstraction.md) | `heuristic` | Keep a function or section focused on one primary conceptual level. |
| [Small Functions](../compendium/small-functions.md) | `heuristic` | Prefer functions that represent one coherent operation and can be understood locally. |
| [Worse Is Better](../compendium/worse-is-better.md) | `design-philosophy` | A simpler, sufficiently correct design can achieve wider adoption and evolve more effectively than a theoretically perfect one. |
| [YAGNI](../compendium/yagni.md) | `heuristic` | Avoid implementing capabilities that are not required by current evidence. |
