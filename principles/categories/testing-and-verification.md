# Testing and Verification

This category groups related concepts for navigation. Category membership does not make every item equally normative.

| Entry | Classification | Summary |
|---|---|---|
| [Arrange–Act–Assert](../compendium/arrange-act-assert.md) | `testing-pattern` | Structure a test around preparation, one primary action, and verification. |
| [FIRST Tests](../compendium/first-tests.md) | `umbrella-concept` | Tests should be fast, independent, repeatable, self-verifying, and timely. |
| [Given–When–Then](../compendium/given-when-then.md) | `testing-pattern` | Describe behavior through context, event, and outcome. |
| [One Logical Behaviour per Test](../compendium/one-logical-behaviour-per-test.md) | `testing-heuristic` | Keep each test focused on one coherent behavior, allowing multiple related assertions. |
| [Red–Green–Refactor](../compendium/red-green-refactor.md) | `development-cycle` | Create a failing test, make it pass minimally, then improve structure while preserving behavior. |
| [Test Behaviour, Not Implementation](../compendium/test-behaviour-not-implementation.md) | `testing-principle` | Prefer assertions on observable contracts over private structure. |
| [Test Pyramid](../compendium/test-pyramid.md) | `testing-strategy` | Use many fast focused tests, fewer integration tests, and a small number of broad end-to-end tests as a starting heuristic. |
| [Test-Driven Development](../compendium/test-driven-development.md) | `development-method` | Use tests to drive small design and implementation increments. |
