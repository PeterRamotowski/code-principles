# Modularity, Object Design, and Locality

This category groups related concepts for navigation. Category membership does not make every item equally normative.

| Entry | Classification | Summary |
|---|---|---|
| [Composition over Inheritance](../compendium/composition-over-inheritance.md) | `heuristic` | Prefer assembling behavior from collaborators over deep implementation inheritance. |
| [Encapsulation](../compendium/encapsulation.md) | `principle` | Control access to state and preserve invariants through a deliberate interface. |
| [High Cohesion, Low Coupling](../compendium/high-cohesion-low-coupling.md) | `principle` | Keep related behavior together while minimizing knowledge between modules. |
| [Information Hiding](../compendium/information-hiding.md) | `principle` | Hide volatile design decisions behind stable boundaries. |
| [Interface Segregation Principle](../compendium/interface-segregation-principle.md) | `principle` | Prefer focused consumer-oriented contracts over broad interfaces. |
| [Law of Demeter](../compendium/law-of-demeter.md) | `heuristic` | Limit knowledge of distant object structure and collaboration chains. |
| [Liskov Substitution Principle](../compendium/liskov-substitution-principle.md) | `principle` | Subtypes must preserve the behavioral contract expected of the base abstraction. |
| [Locality of Behaviour](../compendium/locality-of-behaviour.md) | `principle` | Place behavior near the data, UI, or concept it primarily affects. |
| [Package by Feature](../compendium/package-by-feature.md) | `organizational-principle` | Organize top-level code around capabilities or business features rather than only technical layers. |
| [Separation of Concerns](../compendium/separation-of-concerns.md) | `principle` | Separate responsibilities that represent different concerns or change drivers. |
| [Single Responsibility Principle](../compendium/single-responsibility-principle.md) | `principle` | Give a module one cohesive responsibility or primary reason to change. |
| [Tell, Don’t Ask](../compendium/tell-dont-ask.md) | `heuristic` | Ask behavior-owning objects to perform operations instead of extracting state and deciding externally. |
